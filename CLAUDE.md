# Fermín

Racket sports academy management. MVP is tennis only; padel and pickleball
are modelled but switched off in `lib/domain/sports.ts`. Next.js App
Router, TypeScript, Astryx design system, Supabase.

**Read `docs/SPEC.md` first.** It is the single source of truth for what the
product does and every decision already made. Change it in place when a
decision changes; never add a parallel spec.

Astryx usage rules are in `AGENTS.md` (generated by `npx astryx init`).

## Commands

```bash
npm run dev          # http://localhost:3000
npm run build
npm run typecheck
npm run check        # seed integrity + command interpreter + allocation smoke tests
npm run astryx -- component <Name>   # props for an Astryx component
```

## Layout

```
app/                      routes: / (calendar), /alumnos, /ajustes
components/calendar/      week grid, day grid, chips, toolbar, inspector panels
components/command/       ⌘K bar: search, dictation, action preview
components/students/      families list
components/settings/      academy settings (make-up expiry, mixed levels)
components/shell/         AppShell + TopNav
lib/domain/               types, Spanish labels, training programme
lib/data/                 seed.ts (demo data), store.ts (state + actions + undo)
lib/scheduling/           allocate.ts (auto-allocation engine)
lib/voice/                parse.ts (rules → Slots → ActionDraft), jev.ts (Jev → Slots)
app/api/interpret/        server route that calls Jev (needs TYPESAFE_API_KEY)
lib/weather/              forecast.ts (rain; mock today)
lib/ui/                   state.ts (calendar view state)
supabase/migrations/      schema + RLS; mirrors lib/domain/types.ts
```

## Conventions

- UI text in Spanish. Code, comments, commits and docs in English.
- Use Astryx components for anything they cover. The calendar grid, chips and
  cards are the deliberate exception: CSS Modules, Astryx tokens only.
- No raw hex or px for colour, spacing or radius. Use `var(--color-*)`,
  `var(--spacing-*)`, `var(--radius-*)`, or the Fermín tokens in
  `app/globals.css` (`--lv*` for level, `--fermin-rain*` for rain).
- Blue is rain. Red, orange, green and yellow are levels 1 to 4. Do not use
  these colours for anything else.
- Level must always be readable without colour.
- Domain logic stays in `lib/` as pure functions with no React. Components
  call store actions; they do not edit data themselves.
- Every mutation is a store action, shows a toast with "Deshacer", and can be
  undone. Group multi-step changes in `transaction()`.
- A text or voice command only ever produces `Slots`, then an `ActionDraft`
  through `resolveSlots`. The user confirms it; then a store action runs.
  Jev and the rules must fill the same `Slots`; never let either write data.
- Jev cannot generate text. Model every new command as Choice / Noul / Score
  questions over things that already exist (docs.typesafe.ai).
- Dates are local `YYYY-MM-DD` strings (`lib/dates.ts`). Weekdays are ISO, 1 = Monday.
- Anything that depends on today's date renders on the client only
  (`dynamic(..., {ssr: false})`), to avoid hydration mismatches.
- Icons: `lucide-react` only.
- When `lib/domain/types.ts` changes, change the SQL migration in the same commit.
